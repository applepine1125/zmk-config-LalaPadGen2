# tp-tuner: トラックパッド調整ツール

IQS9151 ドライバのジェスチャ判定値と IC 感度レジスタを USB シリアル経由でその場で変更し、
ドライバが送ったイベントとホストが受け取ったイベントを同じ時間軸で見るためのブラウザアプリ。
ビルド不要・依存なし。`index.html` を Chrome で開くだけで動く。

## 立ち上げ

1. 調整したい側の半分に USB ケーブルを挿す(左右それぞれにシェルが入っている)
2. Chrome で `tools/tp-tuner/index.html` を開き「接続」を押す。右手(central)側はポートが 2 つ見える
   (もう 1 つは ZMK Studio 用で応答しない)ので、どちらかを選ぶ。接続直後に `tp trace off` と `tp info` を
   1.5 秒タイムアウトで送り、いずれかが失敗(タイムアウト含む)すると
   「もう一方のポートを選んでください」と表示して切断するので、再度「接続」を押してもう一方を選ぶ。
   一度接続を許可したポートは、次回からページを開くか USB を挿し直すだけで自動接続される
   (上部の「自動接続」で切れる)
3. 右のカードで「この操作を試す」(またはキー 1〜7)を押してから、カードの「やること」どおりに 1 回だけ動作する。
   カードに「PC の認識: 指 1 本 / 押下 110ms / 移動 3 → タップと認識 → 左クリック 1 回送信 → ホストで左クリック 1 回受信」の
   ような 1 行が出るので、自分の体感と比べて「体感どおり」「反応しなかった」などのボタンで答える。理由と副作用つきの
   パラメータ調整の提案が出るので「適用して再試行」で反映し、もう一度動作する。ホストが受け取ったクリックや
   wheel も認識文に載せたいときは「テスト開始」でカーソルをテストパッドに固定する(`Esc` か「テスト終了」で解除)

Web Serial API が必要なので Chrome または Edge で開くこと(Safari / Firefox は非対応)。
`file://` のまま開いて問題ない。

## 調整ループ(操作を選ぶ → 行う → PC の認識を見る → 体感を答える → 提案を適用 → 再試行)

このツールは合否を判定しない。「PC(ドライバとホスト)が何を認識したか」を人間の言葉で見せ、
それと体感のズレを人間が答えることでパラメータを合わせていく。

- **操作を選ぶ**: カードの「この操作を試す」を押すとそのカードが黄色の「待機中」になり、テストパッドに
  「次の動作を『2本指スクロール』として認識します」と出る。接続中なら同時に `tp trace on` を送るので、テスト開始を
  押していなくても判定材料が届く。待機できるのは 1 枚だけで、もう一度押すと解除、別のカードを押すと切り替わる。
  キー 1〜7 でも選べ、認識後は Space で同じカードをもう一度待機できる(カーソル固定中でも使える)
- **行う**: 指が触れてから離れて 0.4 秒空くまでを 1 回の「試行」として切り出す(タップ後すぐの再接触は同じ試行にまとまる)。
  待機中に来た試行が選択中のカードに反映される(離してから約 1 秒後)。カードを選んでいないときの動作はパッド下の
  1 行にだけ出る
- **PC の認識を見る**: カードに太字 1 行で「事実 → ドライバがどう認識し何を送ったか → ホストが何を受け取ったか」を出す。
  ドライバが何もしなかったときは「ボタン報告なし(押下 320ms > 1f_tap_max_ms=250)」のように、しなかった理由の候補を
  パラメータの現在値つきで書く。「認識の内訳」を開くと指本数・押下時間・移動量・2 回目の接触までの間隔・ドライバの
  報告・ホストの受信・`ret≠0` の有無・段階ごとの事実が見られる
- **体感を答える**: カード種別ごとのボタン(タップ系: 体感どおり / 反応しなかった / 意図と違う動作になった(ドラッグ・別のボタン・
  カーソル移動・2 回クリック)/ 鈍い / 敏感すぎる。タップドラッグ: 入らなかった / 終わらない / 確定が遅い。
  2 本指スクロール: しなかった / 重い / 速すぎ / 遅すぎ / 滑りすぎ / 滑らない / 斜めに暴れる。ピンチ: ならない /
  スクロールになる / 敏感すぎ。カーソル移動: 動き出しが遅い / 軽いタッチを拾わない / 震える / 飛ぶ / 速すぎ / 遅すぎ /
  滑る / 滑らない)
- **提案を適用**: 押した体感と観測値の組み合わせから「対象パラメータ、現在値 → 提案値、理由(観測値を引用)、副作用」を
  1〜4 件出す。「適用して再試行」で `tp set` を送り、同じカードを自動で再待機する。「適用しない」で閉じる。
  観測から絞れない組み合わせは「観測からは原因を絞れません」と出す。速度そのもの(`zip_xy_scaler` /
  `zip_vertical_scroll_scaler`)はキーマップ側なので、ここでは変えられない旨とシステムレイヤーの `ZDS_*` キーを案内する。
  IC 系(感度・周期・フィルタ)を含む提案には「次にパッドへ触れたときに反映」と添える
- **履歴**: カードごとに直近 5 試行を「認識 / 体感 / 適用した変更」で残す(ページ内のみ)
- **カーソル移動カード**(先頭): 動き出し遅延(接触フレームから最初の非ゼロ `rel` までの ms)、移動量合計(ファーム
  `|rel_x|+|rel_y|` の和 / ホスト `movementX/Y` の和)、フレーム間隔の平均、微小動き(`|rel|≤2`)の割合、慣性の有無
  (離した後に `R 0/1` が続いたか)を出す。ポインタ速度そのものは `zip_xy_scaler`(ビルドが必要)で決まる
- 各カードの「関係するパラメータ」を開くと、関係する値を 1 段階ずつ動かせる(押すとそのカードが再待機する)。
  各パラメータには「何を決める値か / 上げると / 下げると」の説明が常に表示され、パラメータ一覧の各行にも同じ説明が出る。
  範囲は `tp list` の min/max でクランプされる
- テストパッド中央には、ドライバが今どう認識しているか(「待機」「指 1 本 移動中」「ボタン押下中(左) ドラッグ」
  「タップ後 2 回目の接触待ち(左ボタン保持中)」「2 本指 スクロール中」「ピンチ中」など)を大きく表示する。
  直近の `T F` 行から導いており、フレームが 0.6 秒途絶えると「待機」に戻る
- パラメータ一覧・タイムライン・診断は画面下の折りたたみにある。細かく値を決めたいときに開く

## 使い方の要点

- 変更は即座にファームに送られる(揮発。再起動で `.conf` の値に戻る)
- IC 系(感度・サンプリング周期・ATI)は次のフレーム処理で書き込まれるので、変更後にパッドへ一度触れる。
  ATI ターゲットや動的フィルタを変えたら「Re-ATI」を押す
- 既定値と異なる行は黄色、`tp set` が `ERR` を返した行は赤で表示される。「既定に戻す」で 1 つずつ、
  「すべて既定に戻す」で全部を既定値に戻せる(`tp reset` を送ったあと `tp list` を取り直す)
- 確定したら「差分を .conf でコピー」して `config/lalapadgen2.conf` に貼り、PR を作って CI でビルドする
- 「プロファイル保存」はブラウザの localStorage に現在の値一式を保存する。「読込」で選んだ
  プロファイルの値を順に `tp set` する(接続中のみ)
- 右手(central)に USB を挿すと ZMK はマウス出力も USB HID に切り替える(左手(peripheral)に挿しても
  ホストへの出力先は変わらない)。BLE 固有の症状(送信キュー詰まり)を見るときはキーマップの
  `&out OUT_BLE` で出力を BLE に戻す
- 2 本指操作がスクロールとピンチのどちらに化けるかは `2f_pinch_ratio_x10`(指の間隔の変化が重心の移動の
  何倍以上ならピンチにするか、×0.1)でも調整できる。下げるとピンチになりやすく(スクロールがピンチに化けやすい)、
  上げるとピンチになりにくく(スクロール寄り)なる
- BLE で動かし続けるとカーソルやスクロールがだんだん遅くなる場合は、送信レートの 2 パラメータ
  (`cursor_report_interval_ms` / `scroll_report_interval_ms`)で報告をまとめて送る間隔を空け、送信量を
  減らして詰まりを緩和できる(上げた分だけ最大で遅れが増える)。右手を USB に挿して症状が消えるかで
  BLE 経路の詰まりかどうかを切り分けられる
- 実機なしで表示を確認したいときは「ダミーデータ」を押す。「カーソル移動」(ゆっくり→速く)、「1本指タップ」
  (押下が長くクリックにならない)、「タップドラッグ」(2 回目の接触が遅い)の 3 試行が投入されるので、体感ボタンを押して
  提案の出方を確認できる(未接続なので「適用して再試行」は押せない)
- 「記録をクリア」で記録・カード・診断をすべて消す

## タイムラインの見方

「タイムライン・診断」を開くと上から順に 6 レーン。表示幅は 2s / 5s / 10s で切り替えられ、「一時停止」で時間を
止めて観察できる。記録は直近 60 秒分だけ保持する。

- FW 指: ドライバが検出した指の本数(0〜3 を高さで表す)
- FW ボタン: ドライバが `input_report` で送ったボタンの押下区間(青=左、緑=右、橙=中)。赤い × は
  `input_report` がイベントを捨てたことを示す
- FW REL/WHEEL: 相対移動(黒)と wheel(赤)の報告
- HOST ボタン: テストパッド上でブラウザが受け取った `buttons` の状態(色は FW ボタンと同じ)
- HOST move: ブラウザが受け取った `pointermove`
- HOST wheel: ブラウザが受け取った `wheel`

診断で問題を検出した時刻には赤い縦線が引かれる。

## 診断の見方

- 「input_report が捨てた」: input キュー満杯でドライバのイベントがホストに届いていない
- 「ホストのボタンが押されたまま」: ドライバは離したのにホスト側でドラッグが残っている(タップ後ドラッグ残りの症状)
- 「wheel が届いていない」: ドライバはスクロールしたのに伝送で落ちている
- 「ドライバが wheel を出していない」: 2 本指移動が `2f_scroll_start_move` などの判定に達していない

## 開発

    node --test tools/tp-tuner/

ロジックは `tuner.js`(純粋関数)、UI は `index.html`。

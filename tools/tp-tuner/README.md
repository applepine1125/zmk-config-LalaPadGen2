# tp-tuner: トラックパッド調整ツール

IQS9151 ドライバのジェスチャ判定値と IC 感度レジスタをその場で変更し、左右のパッドで指の位置と
判定をリアルタイムに見るためのブラウザアプリ。ビルド不要・依存なし。`index.html` を Chrome で
開くだけで動く。

## 立ち上げ(3 ステップ: 接続 → 触って見る → 変えて書き込む)

1. **接続**: USB なら調整したい側の半分にケーブルを挿して「接続」を押す(右手(central)側は
   ポートが 2 つ見えるので、応答するほうを選ぶ。応答しない方を選ぶと「もう一方のポートを選んで
   ください」と出るので選び直す)。BT は `tools/tp-tuner-mac` の Mac ネイティブアプリを使う
   (下記参照)。一度接続を許可したポート/機器は次回から自動接続される(上部の「自動接続」で切れる)
2. **触って見る**: パッドに指で触れると、画面左半分の右手・左手それぞれのパッドに指の位置と判定が
   リアルタイムに出る(USB は接続した側だけ)。画面右半分の「今の操作」に側ごとの現在の状態が
   大きめの文字で出て、その下の「検知した操作」に接触が終わるたびの認識文とクリック・スクロール
   開始が時刻つきで新しい順に積み上がる(同じ内容が連続すると 1 行にまとめて回数が出る)
3. **変えて書き込む**: パラメータ一覧の値を変えるとすぐには送らず保留され(「未書き込み: パッド n 件」)、
   「書き込み」で左右両方(USB では接続側だけ)に一度に反映する

Web Serial API が必要なので Chrome または Edge で開くこと(Safari / Firefox は非対応)。
`file://` のまま開いて問題ない。

## BT で使う(Mac アプリ)

macOS では HID 接続中の BLE デバイスにブラウザ(Web Bluetooth)から GATT アクセスできないため、
BT 接続には `tools/tp-tuner-mac` の Mac ネイティブアプリを使う。ビルド方法は
`tools/tp-tuner-mac/README.md` を参照。アプリは `index.html` と `tuner.js` を自前の WKWebView で
そのまま表示し、USB シリアルの代わりにネイティブ側の橋渡し(BLE / USB シリアル列挙)で接続する。

- 接続すると右手(central)・左手(peripheral)の両方に `info` / `list` を送り、左右を同時に扱う。
  左手が応答しなければヘッダの左手は「✗応答なし」になり、右手だけで続行できる
- ライブ表示のチェックが ON の間、ファームは指の位置を右手 60 回/秒・左手 15 回/秒で流す(左手は
  右手との split リンクを通るので控えめ)。OFF にすると要約(`T S`)だけになる
- パラメータの書き込み・保存など他の操作は USB のときと同じ(左右両方、または詳細設定で片側ずつ)

## 画面の見方

- **ヘッダ**: 接続方式(USB/BT)、左右それぞれの接続状態(✓ または ✗応答なし、保存済みかどうか)、
  未書き込みの状態(例: `未書き込み: パッド 3 件 / キー設定あり`)、タブに関係なく共通の操作ボタン
  (書き込み・再読み込み・デフォルトに戻す・.conf をエクスポート・.keymap をエクスポート)、接続/切断と
  自動接続、その下のプリセット行を固定表示する(パラメータ一覧をスクロールしても押せる)。「書き込み」
  はトラックパッドの未書き込み変更(`set` → `save`)とキー設定の未保存変更(Studio の保存)を両方まとめて
  書き込む。「再読み込み」「デフォルトに戻す」も両方まとめて行い、未書き込みの変更があるときは確認する
- **プリセット行**: `プリセット [選択 ▼] [新規作成] [保存] [削除]` とプリセットとの差分件数。プルダウンで
  プリセットを選ぶと、その内容(タッチパッド + キー設定)を画面に反映する(未書き込みの状態。実機へは
  ヘッダの「書き込み」で書く)。「新規作成」は画面内モーダルで名前を入力し、今の画面の状態を 1 つの
  プリセットとして保存する。「保存」は選択中のプリセットを今の画面の状態で上書きし、「削除」は選択中の
  プリセットを消す。プリセットは Mac アプリでは `~/Library/Application Support/TpTuner/presets.json`、
  ブラウザでは `localStorage` に保存される
- **パッド(画面左半分)**: 右手・左手を横に並べ、それぞれ縦横比 2457:3072 の暗い面に `T F` から
  指の位置を光る点で描いて 300ms で薄れる軌跡を残す。色は待機(灰)/ 1 本指(青)/ 2 本指スクロール・
  2 本指(緑)/ ピンチ(橙)/ 3 本指(紫)で、パッドの枠と側名バッジにも同じ色が出る。hold が立って
  いれば枠が赤くなって「ドラッグ中」、ボタン押下の瞬間はパッド全体が一瞬明るくなる。パッドの下に
  状態(接続・ライブ表示なし・USB では接続側のみ・応答なし)を表示する
- **検知した操作(画面右半分)**: 上段に側ごとの「今の操作」を大きめの文字で表示する(ライブ表示が
  ない側は要約が届くとその認識文を数秒表示する)。下段の「検知した操作」には接触が終わるたびの
  認識文と、クリックの押下・離し、スクロール開始が時刻(HH:MM:SS)・側つきで新しい順に最大 30 件
  積み上がる。同じ内容が連続すると 1 行にまとめて回数を表示する
- **パラメータ**: 左右共通の 1 つの一覧。値を変えると保留(値の横に変更前の値が「← 15」のように出て、
  行が黄色)になり、ヘッダの「書き込み」で左右両方(USB では接続側)に `set` → `save` → 読み直し
  (`info` も取り直して保存状態を更新)を一度に行う。失敗した行は保留のまま残る。ヘッダの
  「再読み込み」は保留を捨てて読み直す。ヘッダの「デフォルトに戻す」は確認のうえ左右を `reset`
  して読み直す。ヘッダの「.conf をエクスポート」は全パラメータの `CONFIG_…` 行をクリップボードへ
  コピーし、下のテキストエリアにも表示する。既定表示の値は右手の値(右手が無ければ左手)で、
  左右で違う行には「左右で違う(右 X / 左 Y)」と印が付く。プリセットを選んでいるときは、差のある
  行に「プリセット: 20」(左右で違えば「プリセット: 右 20 / 左 30」)と印が付く。一覧の上の検索欄に
  文字を入れると、パラメータ名か説明文に部分一致する行だけに絞り込む(大文字小文字は区別しない)。
  パラメータ先頭の「詳細: 左右別に設定」を開くと各行が右/左の 2 列になり、列ごとに保留・書き込みできる。
  enable が OFF だと意味を持たないパラメータ(タップ有効時のみの各種しきい値、ピンチ有効時のみの
  しきい値、慣性系、スクロールの 2 パラメータなど)は、対応する enable(保留値があればそれ、無ければ
  現在値)が OFF の間は行が薄く表示され入力が押せなくなる(値は消えず表示されたまま)。enable の
  チェックを変えると即座に追従する。詳細表示では左右それぞれの値で判定する
- **ポインタロック**: ライブ表示の隣の「ポインタロック」を押すと画面全体を覆うオーバーレイが出て、
  クリック・右クリック・スクロールを Mac に効かせずにこの画面が受け取る(ポインタロックを要求
  するので実機で試す間もカーソルは動かない)。`Esc` で解除する。ポインタロックが使えない環境
  (WKWebView など)では「この環境ではポインタロックできません。クリック・スクロールの既定動作
  だけ止めています(カーソルは動きます)。Esc で解除」と表示してオーバーレイだけで続行し、
  カーソルは動くがクリック・スクロールの既定動作は引き続き止める
- **シリアルログ**: 画面最下部の折りたたみ(既定は閉じている)

## キー設定タブ

ヘッダの「キー設定」タブで ZMK Studio 経由のキーマップ変更ができる(Mac アプリでの BT 接続、
または USB で右手に挿した場合のみ。Web Serial 直結や USB の左手側では使えない)。レイヤーを選び、
図から変えたいキーを選び、右のパネルで behavior と値(キーコード・レイヤー番号など)を選ぶと即座に
キーボードへ送られる(未保存)。キー配列の図には十字キーとトラックパッドのジェスチャ割り当て
(物理レイアウトの位置 42〜67)を表示しない。ファームの keymap からは消えておらず、トラックパッドの
タップ→クリックなどはそのまま動く。ヘッダの「書き込み」でキーボードの flash に保存する。保存すると
`config/lalapadgen2.keymap` は初期値の扱いになり、`settings_reset` を書き込むとこの変更は消える。

## 使い方の要点

- パラメータの変更は「書き込み」を押すまでファームに送られない。ページを開き直したり保留を捨てると
  変更前の値に戻る
- 「書き込み」はパラメータを `set` → `save` の順に送るので、成功すれば接続している側の NVS に保存され、
  以後は BT 接続時もその側は保存した値で起動する。保存状態は `tp info` の応答からヘッダの側名の隣に
  「(保存済み)」「(未保存)」として出る(古いファームでは表示されない)
- IC 系(感度・サンプリング周期・ATI)は次のフレーム処理で書き込まれるので、書き込み後にパッドへ
  一度触れる。ATI ターゲットや動的フィルタを変えたら「Re-ATI」を押す
- 確定した値は「.conf をエクスポート」で `config/lalapadgen2.conf` に貼り、PR を作って CI で
  ビルドする。書き出した値はビルド時の既定値で、アプリからの書き込み(NVS)はそれを上書きして動く
- 右手(central)に USB を挿すと ZMK はマウス出力も USB HID に切り替える(左手(peripheral)に挿しても
  ホストへの出力先は変わらない)。BLE 固有の症状(送信キュー詰まり)を見るときはキーマップの
  `&out OUT_BLE` で出力を BLE に戻す
- 2 本指操作がスクロールとピンチのどちらに化けるかは `2f_pinch_ratio_x10`(指の間隔の変化が重心の
  移動の何倍以上ならピンチにするか、×0.1)でも調整できる。下げるとピンチになりやすく、上げると
  ピンチになりにくく(スクロール寄り)なる
- BLE で動かし続けるとカーソルやスクロールがだんだん遅くなる場合は、送信レートの 2 パラメータ
  (`cursor_report_interval_ms` / `scroll_report_interval_ms`)で報告をまとめて送る間隔を空け、送信量を
  減らして詰まりを緩和できる。右手を USB に挿して症状が消えるかで BLE 経路の詰まりかどうかを
  切り分けられる
- 実機なしで表示を確認したいときは `?fakeNative=1` を付けて開く。両手を模擬した機器に接続でき、
  `&fakeLive=1` を足すと右手のパッドに 1 本指の円運動→2 本指スクロールを繰り返すダミーのフレームが
  流れる。キー設定タブは接続すると自動で模擬の物理レイアウト(6 キー)・レイヤー(Default/Fn)・
  behavior(Key Press/Momentary Layer/Transparent)が読み込まれる。`&fakeStudioLocked=1` を足すと
  ロック中の表示を確認できる

## 開発

    node --test tools/tp-tuner/

ロジックは `tuner.js`(パラメータ調整、純粋関数)と `keymap_ui.js`(キー設定タブの表示・判定、
純粋関数)、ZMK Studio RPC クライアントは `studio.js`、キーコード表は `keycodes.js`。`presets.js` は
プリセットのスナップショット作成・差分計算・反映内容の計算・保存形式(`presets.json`)の検証と更新を
行う純粋関数群で、画面の状態とキーボードの実値からプリセットとの差分を出すのに使う。UI は
`index.html`。`dev/fake-native.js` は実機なしで Mac アプリの橋渡し
(`window.webkit.messageHandlers.tpTuner`、ZMK Studio RPC 込み、プリセットの読み書きも含む)を模擬する
開発用スタブで、`?fakeNative=1` を付けたときだけ読み込まれる。

# tp-tuner: トラックパッド調整ツール

IQS9151 ドライバのジェスチャ判定値と IC 感度レジスタをその場で変更し、左右のパッドで指の位置と
判定をリアルタイムに見るためのブラウザアプリ。ビルド不要・依存なし。`index.html` を Chrome で
開くだけで動く。

## 立ち上げ(3 ステップ: 接続 → 触って見る → 変えて書き込む)

1. **接続**: USB なら調整したい側の半分にケーブルを挿して「接続」を押す(右手(central)側は
   ポートが 2 つ見えるので、応答するほうを選ぶ。応答しない方を選ぶと「もう一方のポートを選んで
   ください」と出るので選び直す)。BT は `tools/tp-tuner-mac` の Mac ネイティブアプリを使う
   (下記参照)。一度接続を許可したポート/機器は次回から自動接続される(上部の「自動接続」で切れる)
2. **触って見る**: パッドに指で触れると、画面左半分の右手・左手それぞれのパッドに指の位置と判定が
   リアルタイムに出る(USB は接続した側だけ)。画面右半分の「今の操作」に側ごとの現在の状態が
   大きめの文字で出て、その下の「検知した操作」に接触が終わるたびの認識文とクリック・スクロール
   開始が時刻つきで新しい順に積み上がる(同じ内容が連続すると 1 行にまとめて回数が出る)
3. **変えて書き込む**: パラメータ一覧の値を変えるとすぐには送らず保留され(「未書き込みの変更 n 件」)、
   「書き込む」で左右両方(USB では接続側だけ)に一度に反映する

Web Serial API が必要なので Chrome または Edge で開くこと(Safari / Firefox は非対応)。
`file://` のまま開いて問題ない。

## BT で使う(Mac アプリ)

macOS では HID 接続中の BLE デバイスにブラウザ(Web Bluetooth)から GATT アクセスできないため、
BT 接続には `tools/tp-tuner-mac` の Mac ネイティブアプリを使う。ビルド方法は
`tools/tp-tuner-mac/README.md` を参照。アプリは `index.html` と `tuner.js` を自前の WKWebView で
そのまま表示し、USB シリアルの代わりにネイティブ側の橋渡し(BLE / USB シリアル列挙)で接続する。

- 接続すると右手(central)・左手(peripheral)の両方に `info` / `list` を送り、左右を同時に扱う。
  左手が応答しなければヘッダの左手は「✗応答なし」になり、右手だけで続行できる
- ライブ表示のチェックが ON の間、ファームは指の位置を右手 60 回/秒・左手 15 回/秒で流す(左手は
  右手との split リンクを通るので控えめ)。OFF にすると要約(`T S`)だけになる
- パラメータの書き込み・保存など他の操作は USB のときと同じ(左右両方、または詳細設定で片側ずつ)

## 画面の見方

- **ヘッダ**: 接続方式(USB/BT)、左右それぞれの接続状態(✓ または ✗応答なし、保存済みかどうか)、
  未書き込みの変更件数、接続/切断と自動接続だけを出す
- **パッド(画面左半分)**: 右手・左手を横に並べ、それぞれ縦横比 2457:3072 の暗い面に `T F` から
  指の位置を光る点で描いて 300ms で薄れる軌跡を残す。色は待機(灰)/ 1 本指(青)/ 2 本指スクロール・
  2 本指(緑)/ ピンチ(橙)/ 3 本指(紫)で、パッドの枠と側名バッジにも同じ色が出る。hold が立って
  いれば枠が赤くなって「ドラッグ中」、ボタン押下の瞬間はパッド全体が一瞬明るくなる。パッドの下に
  状態(接続・ライブ表示なし・USB では接続側のみ・応答なし)を表示する
- **検知した操作(画面右半分)**: 上段に側ごとの「今の操作」を大きめの文字で表示する(ライブ表示が
  ない側は要約が届くとその認識文を数秒表示する)。下段の「検知した操作」には接触が終わるたびの
  認識文と、クリックの押下・離し、スクロール開始が時刻(mm:ss.s)・側つきで新しい順に最大 30 件
  積み上がる。同じ内容が連続すると 1 行にまとめて回数を表示する
- **パラメータ**: 左右共通の 1 つの一覧。値を変えると保留(値の横に「→ 新しい値」、行が黄色)になり、
  「書き込む」で左右両方(USB では接続側)に `set` → `save` → 読み直しを一度に行う。失敗した行は
  保留のまま残る。「再読み込み」は保留を捨てて読み直す。「全て既定に」は確認のうえ左右を `reset`
  して読み直す。「.conf をエクスポート」は全パラメータの `CONFIG_…` 行をクリップボードへコピーし、
  下のテキストエリアにも表示する。既定表示の値は右手の値(右手が無ければ左手)で、左右で違う行には
  「左右で違う(右 X / 左 Y)」と印が付く。「詳細: 左右別に設定」を開くと各行が右/左の 2 列になり、
  列ごとに保留・書き込みできる
- **タイムライン**: 幅 10 秒固定で 3 レーン(指の本数・ファームが送った操作・Mac が受けた操作)。
  Mac が受けた操作は `document` 全体の `pointerdown/up/move`・`wheel` を見ており、ポインタロックは
  使わないためアプリのウィンドウ上でのみ検出できる。BLE で両側から来るときは印に側の文字を添える
- **確認モード**: ライブ表示の隣の「確認モード」を押すと画面全体を覆うオーバーレイが出て、
  クリック・右クリック・スクロールを他のアプリに影響させずにこの画面が受け取る(ポインタロックを
  要求するので実機で試す間もカーソルは動かない)。`Esc` で終了する。ポインタロックが使えない環境
  (WKWebView など)ではオーバーレイだけで続行し、カーソルは動くがクリック・スクロールの既定動作は
  引き続き止める
- **診断**: input_report のドロップ・ホストのボタン押しっぱなし・wheel の未達・2 本指スクロール
  なのに wheel を出していない、の 4 種類をタイムラインの下に一覧で出す
- **シリアルログ**: 画面最下部の折りたたみ(既定は閉じている)

## 使い方の要点

- 変更は「書き込む」を押すまでファームに送られない。ページを開き直したり保留を捨てると変更前の
  値に戻る
- 「書き込む」は `set` → `save` の順に送るので、成功すれば接続している側の NVS に保存され、以後は
  BT 接続時もその側は保存した値で起動する。保存状態は `tp info` の応答からヘッダの側名の隣に
  「(保存済み)」「(未保存)」として出る(古いファームでは表示されない)
- IC 系(感度・サンプリング周期・ATI)は次のフレーム処理で書き込まれるので、書き込み後にパッドへ
  一度触れる。ATI ターゲットや動的フィルタを変えたら「Re-ATI」を押す
- 確定した値は「.conf をエクスポート」で `config/lalapadgen2.conf` に貼り、PR を作って CI で
  ビルドする。書き出した値はビルド時の既定値で、アプリからの書き込み(NVS)はそれを上書きして動く
- 右手(central)に USB を挿すと ZMK はマウス出力も USB HID に切り替える(左手(peripheral)に挿しても
  ホストへの出力先は変わらない)。BLE 固有の症状(送信キュー詰まり)を見るときはキーマップの
  `&out OUT_BLE` で出力を BLE に戻す
- 2 本指操作がスクロールとピンチのどちらに化けるかは `2f_pinch_ratio_x10`(指の間隔の変化が重心の
  移動の何倍以上ならピンチにするか、×0.1)でも調整できる。下げるとピンチになりやすく、上げると
  ピンチになりにくく(スクロール寄り)なる
- BLE で動かし続けるとカーソルやスクロールがだんだん遅くなる場合は、送信レートの 2 パラメータ
  (`cursor_report_interval_ms` / `scroll_report_interval_ms`)で報告をまとめて送る間隔を空け、送信量を
  減らして詰まりを緩和できる。右手を USB に挿して症状が消えるかで BLE 経路の詰まりかどうかを
  切り分けられる
- 実機なしで表示を確認したいときは `?fakeNative=1` を付けて開く。両手を模擬した機器に接続でき、
  `&fakeLive=1` を足すと右手のパッドに 1 本指の円運動→2 本指スクロールを繰り返すダミーのフレームが
  流れる

## 開発

    node --test tools/tp-tuner/

ロジックは `tuner.js`(純粋関数)、UI は `index.html`。`dev/fake-native.js` は実機なしで
Mac アプリの橋渡し(`window.webkit.messageHandlers.tpTuner`)を模擬する開発用スタブで、
`?fakeNative=1` を付けたときだけ読み込まれる。

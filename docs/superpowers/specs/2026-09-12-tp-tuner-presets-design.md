# tp-tuner プリセット・共通操作行・パラメータ検索 設計

## 目的

キーボードの設定リセット(`settings_reset`)でトラックパッドのパラメータと ZMK Studio のキー設定が
消えても、Mac 側に残した設定からすぐ戻せるようにする。あわせて、別経路(ZMK Studio の Web 版や別の Mac)で
キーボードの設定が変わったときに、手元のプリセットとの違いが見えるようにして、意図しない上書きを防ぐ。

## 画面構成

### 共通操作行(1 行目)

タブ(タッチパッド設定 / キー設定)に関係なく同じ行を出す。従来のタブごとの行
(`trackpadActions` / `keymapActions`)は廃止する。

| ボタン | 動作 |
| --- | --- |
| 書き込み | トラックパッドの未書き込み変更(`tp set` + `tp save`)と、キー設定の未保存変更(Studio `saveChanges`)を両方書き込む。プリセットには保存しない |
| 再読み込み | 未書き込みの変更があれば確認モーダルを出す。トラックパッドは `tp list` を読み直し、キー設定は `discardChanges` 後に読み直す |
| デフォルトに戻す | 確認モーダルを 1 回出し、トラックパッドは `tp reset`、キー設定は Studio `resetSettings` でファーム既定に戻す |
| .conf をエクスポート | 従来どおり |
| .keymap をエクスポート | 従来どおり |

- 書き込みボタンの横に未書き込み状態を出す(例: `未書き込み: パッド 3 件 / キー設定あり`)
- Studio が使えない接続(左手 USB、ブラウザ版など)では、キー設定側の処理は飛ばし、ステータスにその旨を出す

### プリセット行(2 行目)

`プリセット [選択 ▼] [新規作成] [保存] [削除]  プリセットとの差分 N 件`

| 操作 | 動作 |
| --- | --- |
| 選択 | プルダウン。プリセットが 1 つもない、または未選択のときは「無し」。プリセットを選ぶと、その内容を画面に反映する(未書き込みの状態。キーボードへは「書き込み」で書く)。未書き込みの変更があるときは確認モーダルを出す。「無し」を選ぶと選択を外すだけで画面は変えない |
| 新規作成 | 画面内モーダルで名前を入力し、今の画面の状態(タッチパッド + キー設定)を 1 つのプリセットとして作り、選択状態にする。空の名前・既存と同じ名前は受け付けない |
| 保存 | 選択中のプリセットを今の画面の状態で上書きする。確認モーダルを出す。未選択なら押せない |
| 削除 | 選択中のプリセットを削除する。確認モーダルを出す。削除後の選択は「無し」。未選択なら押せない |

- 最後に選んだプリセットを覚えておく。起動・接続時は画面に反映せず、差分表示だけ出す
- 名前入力のモーダルはページ内の `<dialog>` で作る(WKWebView は `window.prompt` を実装しないと常に null を返すため)。確認モーダルは従来どおり `window.confirm`(Mac アプリは NSAlert)

## プリセットとの差分表示

比較するのは常に「画面の状態」と「選択中のプリセット」。画面の状態は、トラックパッドがキーボードの値に未書き込みの変更を重ねたもの、キー設定がキーボードの RAM 上の keymap(Studio で変更済み・未保存を含む)。

- 再読み込み直後は画面 = キーボードなので、キーボードとプリセットの差が見える
- プリセットを選んだ直後は差分 0 になり、代わりに未書き込みの印が付く
- 差分表示は印を付けるだけで、画面やキーボードを自動で変えない。ユーザーが差を見て設定を直すか、そのまま書き込むかを決める

表示:

- パラメータ行: `プリセット: 20`。左右で値が違うときは `プリセット: 右 20 / 左 30`。詳細(左右別)表示では各セルに出す
- キー: 差のあるキーキャップの枠を強調し、差のあるレイヤーのボタンに印を付ける。キーを選ぶと編集パネルに `プリセット: ⌘C` のようにプリセット側の割り当てを出す
- レイヤー数が違うときはキー配列の上に `プリセットはレイヤー 5 個(今は 4 個)` を出す
- プリセット行の `プリセットとの差分 N 件` はパラメータ(名前 × 側)とキー(レイヤー × 位置)の差の数、レイヤー数の違いは 1 件として数える

キー設定の読み込み(Studio)は、差分とプリセット操作に必要なので、接続後はタブに関係なく自動で行う。読み込み中はトラックパッドのライブ表示を止め、終わったらタッチパッド設定タブならライブ表示を戻す。

## プリセットの中身と保存先

保存先は Mac アプリでは `~/Library/Application Support/TpTuner/presets.json`、ブラウザで開いた場合は `localStorage`(キー `tp-tuner.presets`)。

```json
{
  "version": 1,
  "selectedId": "p-1757640000000-ab12",
  "presets": [
    {
      "id": "p-1757640000000-ab12",
      "name": "普段使い",
      "createdAt": "2026-09-12T10:00:00.000Z",
      "updatedAt": "2026-09-12T10:00:00.000Z",
      "trackpad": { "R": { "1f_tap_max_ms": 250 }, "L": { "1f_tap_max_ms": 250 } },
      "keymap": {
        "layers": [
          { "name": "Default", "bindings": [ { "behavior": "Key Press", "param1": 20, "param2": 0 }, null ] }
        ]
      }
    }
  ]
}
```

- `trackpad`: 側(`R` / `L`)ごとに全パラメータを名前 → 値で持つ。読めていない側は持たない
- `keymap.layers`: レイヤー番号順。`bindings` はキー位置順で、非表示位置は `null`
- behavior はファームのビルドで ID が変わりうるため `displayName` で持ち、反映時に名前で ID を引く
- レイヤーを指すパラメータ(`&mo 1` など、behavior のメタデータで `layerId` のスロット)は `{ "layer": 1 }` のようにレイヤー番号で持ち、反映時にその番号のレイヤー ID に直す
- 保存時に読めていない部分(Studio が使えずキー設定を読めていない等)は、既存プリセットの該当部分を残す。新規作成時は `null` にし、ステータスで「キー設定は含まれていません」と知らせる
- 壊れた JSON や未知の `version` は読み込まず、空として扱い、ステータスでエラーを出す(ファイルは上書きしない)

反映の規則:

- トラックパッド: プリセットとキーボードの両方にあるパラメータだけを対象にし、キーボードの値と違うものを未書き込みの変更にする。プリセットにないパラメータ(後からファームに追加されたもの)とキーボードにないパラメータは対象外
- キー設定: レイヤー数が違えば Studio の `addLayer` / `removeLayer`(末尾から)で合わせてから、差のある位置に `setLayerBinding` を送る。behavior 名が見つからない位置は飛ばし、件数をステータスに出す。レイヤー名は Studio クライアントに変更 API がないため反映しない

## 非表示にするキー位置

キー設定タブで、十字キー(位置 42〜51)とトラックパッドのジェスチャ割り当て(位置 52〜67)を表示しない
(`config/boards/shields/lalapadgen2/lalapadgen2-layouts.dtsi`)。ファームの keymap からは消さない
(トラックパッドのタップ → クリック等はこの割り当てで動いている)。非表示位置はプリセットの保存・差分・反映の対象外、`.keymap` のエクスポートには含める。配列図の大きさは表示するキーだけで計算する。

## パラメータ表示の改善

- on/off 型(`driver_bool`)の値は、未書き込みの印・左右差の説明・プリセット差分で `ON` / `OFF` と表示する
- 「詳細: 左右別に設定」のすぐ上に検索欄を置き、パラメータ名と説明文の部分一致(大文字小文字を区別しない)で行を絞り込む。該当する行がないグループは隠す
- 左右共通表示でも、側ごとの未書き込み変更(プリセット反映で左右別の値が入った場合)を画面の値として扱い、左右差の説明は画面の値で出す。共通表示で値を変えたら、その名前の側ごとの未書き込み変更は消す

## モジュール構成

| ファイル | 役割 |
| --- | --- |
| `tools/tp-tuner/presets.js`(新規) | 純粋関数。スナップショット作成、差分計算、反映内容の計算、保存形式の検証と更新 |
| `tools/tp-tuner/tuner.js` | `formatParamValue`、`paramMatchesQuery` を追加 |
| `tools/tp-tuner/keymap_ui.js` | 非表示キー位置の定義を追加 |
| `tools/tp-tuner/app_link.js` | プリセットの読み書き(ネイティブ橋渡し / localStorage) |
| `tools/tp-tuner/app_params.js` | ON/OFF 表示、検索、プリセット差分の印、スナップショット取得・反映 |
| `tools/tp-tuner/app_keymap.js` | 非表示キー、タブ非依存の読み込み、プリセット差分の印、スナップショット取得・反映 |
| `tools/tp-tuner/app_presets.js`(新規) | プリセット行の操作と状態 |
| `tools/tp-tuner/app_main.js` | 共通操作行 |
| `tools/tp-tuner-mac/Sources/WebBridge.swift` | `presetsLoad` / `presetsSave` の処理 |
| `tools/tp-tuner/dev/fake-native.js` | `presetsLoad` / `presetsSave` の模擬 |

ネイティブ橋渡しのメッセージ:

- ページ → アプリ `{ type: 'presetsLoad' }` → アプリ → ページ `{ type: 'presetsLoaded', ok, text?, error? }`(ファイルが無いときは `ok: true` で `text` なし)
- ページ → アプリ `{ type: 'presetsSave', text }` → アプリ → ページ `{ type: 'presetsSaved', ok, error? }`(一時ファイルに書いてから置き換える)
